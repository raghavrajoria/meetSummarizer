# GPU/Kaggle procedure
Use Python 3.11 on a CUDA host, separate from backend/LLM environments. Install `pip install -r requirements-ml.txt`; export HF_TOKEN after accepting the pyannote model terms, PYANNOTE_MODEL and PYANNOTE_DEVICE=cuda. No GPU models run on the owner workstation.

Extract mono audio with ffmpeg, then `python scripts/diarize.py recording.wav speaker_turns.csv`. The command refuses to overwrite an existing CSV. Output columns are start,end,speaker in recording-relative seconds. Upload CSV alongside recording/imported ASR; the worker assigns each segment to the turn with maximum positive overlap. It does not invent identities from anonymous clusters.

Pinned pyannote 4 returns DiarizeOutput; older releases return Annotation. `pyannote_turns` handles `.speaker_diarization.itertracks` and direct `.itertracks`, tested with fake outputs. The actual pinned GPU stack/model loading and diarization accuracy require the teammate GPU host; no claim of real-model execution here. The canonical ASR implementation is indicmeet/asr.py (reconstructed v2); no original Kaggle notebook was available to establish byte-for-byte equivalence. Device and compute type are environment controlled; CPU large-model loading fails clearly before imports.

LiveKit composite recordings use session.json/events.jsonl to name clusters by cumulative time overlap. Mic-on is not speaking evidence. Ties remain unnamed. Event times are relative milliseconds; UTC timestamp_ms fallback requires timezone-bearing manifest timestamps. Per-participant tracks require the recording developer to supply tracks aligned to the recording clock; when has_per_participant_tracks=true, completion requires tracks/<identity>.ogg for every participant. Tracks must be padded to the composite recording clock (sample zero equals recording start). The worker transcribes each track with that identity, merges by time and bypasses cluster naming. Missing tracks reject completion.
